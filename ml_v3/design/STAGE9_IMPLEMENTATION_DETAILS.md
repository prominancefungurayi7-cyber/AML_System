# Stage 9 implementation choices recorded before generation

The seven copied Stage 8 documents remain byte-identical and authoritative. This addendum fills the materialization choices those documents explicitly left for implementation. It changes no onset predicate or budget. No generated dataset or model result was available when these choices were recorded.

- Master generation seed: `2026092209`; generator version `stage9.1`. RNG substreams use SHA-256 of dataset identity, seed, partition and component name. The 180-day horizon starts 2026-01-01 00:00:00 UTC. All entity IDs have an opaque `v3w_` / `v3a_` namespace. IDs and event ties carry no class code.
- Every wallet opens with 250,000,000 minor units and every agent with 5,000,000,000 minor units, fixed before events and independent of origin/target. All entities are active from the horizon start. No top-ups are inserted. The audit rejects infeasibility rather than repairing a stream after labels.
- Exact episode counts, lengths, origin budgets, type/channel margins and strengths follow Stage 8. Largest-remainder integer allocation resolves quota fractions, ties in declared type order. Each network episode reserves four W2W slots before remaining subtype quotas are distributed. This is structural graph capacity, not a guarantee that an alert occurs.
- Warm-up includes two events per wallet and twelve cash services per agent, taken from the routine budget and its category inventory. The remaining warm-up and later routine events use shared activity-weighted subjects and agents. No labels are consulted. First wallet observations occur during days 0–7; additional service coverage lies within days 0–35.
- Shared base duration draws are uniform within the frozen family supports. S1 has the shared 25% one-event continuation branch 1–3 days later. S3 has the shared 25% repeat-day branch, with 1 through `min(4, length//6-1)` additional days. All full episodes fit inside days 35–180.
- Strength-mode counts are 20/50/30 over each family's 100 campaigns: Train 12/30/18, Validation 3/7/5, Final Test 3/8/4, Independent 2/5/3. Legitimate subtype groups use the same scaled mixture, privately named coordination modes, not malicious-strength labels. Modes draw Beta(2,3), Beta(2,2), Beta(3,2). Normalized interior offsets use `u**(0.7+coordination)`; S1/S3/A3 additionally use 2–4 clusters with width `0.1 + 0.2*(1-coordination)`. Endpoints of the chosen duration are included.
- Both sides of each matched subtype use the same amount constructors and observation-type/channel recipe. S1 uses an unequal Gamma(0.8,1) composition of a shared USD 300–60,000 total with the common per-event support. S2 uses a shared anchor, an 85% anchor-near branch, and widths 0.015/0.04/0.07/0.20. S4 uses a uniformly chosen 25–60% band-member count. Rejection for bounded amount feasibility is permitted before evaluation; no rejection consults a predicate, target, prevalence or model.
- N1/N2 select 3–12 counterparties and a center and retain real W2W collection/dispersion edges. N3 packs the transfer slots into complete 2–6-edge cycles with distinct nodes within each cycle. Intermediate amount ratios are sampled from [0.2,2.0] relative to the preceding amount and closing/first ratios from [0.2,1.4], rejected only if the common monetary support is exceeded. These ranges are deliberately not the reference predicate's qualifying interval.
- N4 sorts cash funding, W2W movements, then cash exits. Its first W2W enters the center; later movements leave it. The shared planned onward fraction is uniform [0.35,1.05] of planned cash/transfer funding, split into unequal bounded positive amounts. Opening balances can support an amount above observed-window funding without manufacturing money. The universal reference still uses the frozen anchor/window and exact 0.50–1.00 condition.
- Agent A1 campaign populations favor least-served wallets in the preceding 28d; its legitimate counterpart favors previously served wallets. A2 chooses 2–6 designated wallets and allocates a sampled 35–85% of episode events to them; the legitimate counterpart draws designated wallets from prior frequent service where available. A3 uses the shared cluster constructor. A4 orders a sampled dominant cash direction first, with later balancing; its legitimate counterpart can align that direction to actual prior cash demand. All counterpart rules use observable earlier facts only and share mediation/amount/duration recipes. None guarantees a particular target.
- Assisted W2W in agent families services the sender. In other families a shared fair coin selects sender or receiver. Direct transfers never receive agent/service fields. Background events remain interleaved and may themselves satisfy reference conditions.
- Reports publish actual target counts for every partition under Stage 9's explicit generation-audit authorization. These are generation-stage summaries, not a development loader or a public integrity certificate. The public certificate contains opaque commitments and no evaluation file paths or label counts. Development code must never import the generation/audit modules or parse evaluation generation summaries to guide models.
- One permanent generation is allowed. Train/Validation receive temporary reproducibility copies. Evaluation copies are regenerated in memory and compared during the same authorized pre-seal generation phase. Structural audit may read new evaluation files once in that phase. No evaluation file is reopened after the seal marker is written.

Implementation errors discovered with hand-built tests may be corrected before generation. A contradiction with an exact frozen contract requires a stop report. Unexpected prevalence or an audit flag must be reported; it cannot trigger seed search or model-informed regeneration.
